# 理解消息状态

工作台中的消息可能先保存，再由渠道异步投递。不同状态代表的完成程度不同。

## 常见状态

- **处理中**：系统正在生成或投递，不要重复发送。
- **已接受**：发送任务已进入投递链路，但不一定已到客户客户端。
- **已投递或已发送**：渠道确认已处理；重要消息仍建议在真实客户端抽查。
- **失败**：消息没有完成投递，需要查看失败原因后重试。

## 刷新后的判断

临时消息必须在刷新后仍存在，才说明已被系统保存。消息顺序应以服务端记录为准，不应因流式完成而跳动。

## 处理失败

不要连续点击发送。先打开执行链路或失败日志，确认是权限、渠道、内容、安全检查还是外部平台问题。
