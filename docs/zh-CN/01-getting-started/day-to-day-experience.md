# YundaDesk 的日常使用体验

YundaDesk 把不同客户渠道的会话、客户上下文、AI 客服和人工协作放进同一个工作区。这篇文章从首次配置到日常运营，说明团队实际会看到什么、哪些工作可以自动完成，以及哪些操作仍需要人工判断。

具体可用渠道、应用、套餐和操作能力可能因工作区而不同，请以当前产品页面显示为准。

## 从配置到第一次真实接待

开始使用时，团队通常按以下顺序完成设置：

1. 在 **渠道** 中连接网站聊天、Telegram 或当前工作区提供的其他渠道，并完成一次真实收发测试。
2. 新建客户接待 Agent，选择一个 Role，配置服务风格、知识范围、技能和必要能力。
3. 把 Agent 绑定到需要 AI 接待的渠道。一个渠道同一时间只由一个 Agent 接待；没有绑定 Agent 的渠道仍可接收消息，但不会由 AI 自动回复。
4. 上传文档、同步网站或连接当前可用的知识来源，等待页面显示内容已经可以参与回答。
5. 从 **AI Agents** 页面发起 **测试对话**，检查回答内容、使用的知识、技能和转人工边界。
6. 在真实客户侧再次发送测试消息，确认客户确实收到回复。配置成功或页面显示已发送，都不能替代真实渠道的最终验收。

完成这些步骤后，团队不需要在每个渠道的后台分别处理日常会话；客户消息会进入统一工作台。

## 团队每天如何处理会话

坐席在工作台中查看新消息、负责人、会话状态和客户资料。搜索和筛选可以帮助团队按渠道、负责人或状态找到目标会话；分配、转接和内部备注让多人协作时保持清晰的处理责任。

当渠道绑定了已启用的 Agent 时，AI 客服可以先接待。人工坐席能够查看客户消息和 AI 回复，在需要时接管会话，并继续使用同一份客户上下文。客户要求人工、AI 缺少可靠依据或命中转人工条件时，会话会交给团队继续处理。

客户档案把已确认的渠道身份、历史会话、标签、备注和客户记忆集中展示。连接的业务应用还可能提供订单或行为摘要；没有接入对应数据源时，页面不会编造这些信息。

## AI 客服自动完成什么

AI 客服会根据当前 Agent 的知识范围、技能、服务风格、可用能力和客户上下文生成回复。不同 Agent 可以分别负责售前、售后或其他接待职责，并绑定不同渠道。

AI 可以自动参与当前允许的客户会话，但不会因为一次人工回复就立即改变所有后续答案。优秀回复、纠正和未解决问题可以形成改进建议；团队确认采纳后，相关内容才会进入知识、技能或其他明确目标。技能还需要完成相应测试并启用后才会生效。

当知识不足、必要数据不可用、权限不满足或外部能力失败时，AI 应说明限制、请求补充信息或转交人工，而不是猜测订单、政策或客户事实。

## Yuna 在团队内部做什么

Yuna 面向商户团队，不直接充当客户正在对话的接待 Agent。你可以让 Yuna：

- 解读工作区中的会话、客户、报告和当前设置；
- 查找产品操作方法并说明入口、步骤和验证方式；
- 帮助准备渠道、Agent、知识和团队设置；
- 把业务规则整理成待审阅的学习内容；
- 汇总需要确认、失败或待跟进的任务。

只读问题通常可以直接回答。会发送消息、影响客户或进行重要配置变更的操作，会先展示目标、内容或变更预览；只有在当前成员具备权限并完成必要确认后才会执行。重要操作完成后，应查看执行结果，并在对应页面或真实渠道再次验证。

## 知识如何进入回答

知识可以来自上传的文档、同步的网站、连接的文档来源和团队维护的问答。页面会显示处理或同步状态；只有已经准备完成且属于当前 Agent 知识范围的内容，才应参与回答。

团队可以在测试对话或回答详情中检查命中的知识和技能。如果答案不正确，先确认来源内容是否最新、Agent 是否绑定了正确知识，以及内容是否处理完成。纠正现有事实与教 AI 学习新的处理方法是两种不同操作，都需要明确目标和后续验证。

## 团队能看到哪些结果

报告页可按页面提供的时间范围和维度查看会话量、消息趋势、团队接待情况、AI 参与、自动解决、转人工、客户满意度以及 AI 用量。不同报告的统计口径可能不同，应同时查看时间范围、筛选条件和样本量。

这些数据用于发现高频问题、知识缺口、渠道投递问题和人工负载，不代表每一条会话都已正确解决。重要结论应回到具体会话、回答详情和真实送达结果中核对。

## 渠道、应用和主动触达

渠道负责收发客户消息；应用提供订单、客户或其他业务上下文。可用数据和操作取决于当前工作区已连接的渠道、应用、权限和实际状态。实时订单或物流问题应使用已连接的业务能力查询，不能只依赖静态知识文章。

主动触达可用于准备跟进、广播或分群消息。草稿、目标人群和发送策略需要按页面提示审阅；只有真实发送结果或失败原因才能证明消息是否送达。改变频率或安静时段等策略，不等于已经创建或发送一条消息。

## 一套可靠的日常节奏

团队可以采用以下节奏：

1. 查看新会话、待回复和需要人工处理的任务。
2. 处理 AI 转交、渠道失败和客户跟进。
3. 审阅改进建议，更新过时知识并重新测试关键问题。
4. 查看报告中的变化，再回到具体会话确认原因。
5. 新增渠道、能力或自动化后，先预览和测试，再逐步开放给真实客户。

这样可以让 AI 承担重复接待，同时保留人工对知识、风险、客户承诺和真实发送结果的控制。
