# 设置 Agent 名称和回复风格

每个 Agent 都有独立的客户可见名称和回复偏好。修改一个 Agent 不会覆盖其他 Agent。

## 设置步骤

1. 打开 **AI Agents**，选择目标 Agent。
2. 在 **Role** 中编辑名称并确认 Role。
3. 在“商家补充要求”中填写适用于所有客户的品牌偏好。
4. 选择语气风格，并根据需要开启或关闭 emoji。
5. 如希望 AI 在回答前进行更充分的分析，开启“深度思考”。客户不会看到思考过程，回复可能稍慢。
6. 如希望 AI 在完成一个可确认的阶段结果后先发送，再继续处理同一问题的下一阶段，开启“渐进式回答”。
7. 如需编辑在线排队与无人在线话术，切换到“转人工”；完成后保存。

也可以直接告诉 Yuna 要修改哪个 Agent 的哪一项。Yuna 会先确认目标并给出差量草稿；确认后才应用。未提到的配置不会一起被改掉。

## 验证效果

在 **AI Agents** 页的 **测试对话** 中提出一个典型客户问题，检查称呼、语气和格式。开启“渐进式回答”时，可使用一个确实需要多个可用业务步骤的问题验证；测试对话会按真实回答顺序显示已经形成的独立气泡，但不会把测试消息发送给客户。普通回答仍显示为一个气泡。随后在真实渠道抽查一条回复，因为渠道上下文可能影响最终表达。

开启“深度思考”后，打开该次回答的 Trace，应能看到“深度思考”步骤和“仅 Trace 可见”标记。即使没有可展示的思考文本，Trace 仍会显示本次回答已启用深度思考；客户始终只看到最终回复。

开启“渐进式回答”后，AI 客服只有在已经取得一个可确认的阶段结果、且同一问题仍需继续处理时，才会先发送该结果。普通回答、单一澄清或尚无可确认结果时仍只发送一条最终回答；它不会为了增加气泡发送“稍等”或“正在查询”等空话。关闭后，每轮只发送一条最终回答。客户继续输入时，AI 仍会按最新消息重新处理；这项可靠性不受该开关影响。

## 回复语言

AI 客服按客户当前这条消息的语言回复。浏览器界面语言、渠道保存的 locale、AI 客服角色说明、上一轮回复和知识资料的语言都不会覆盖当前消息。客户只发送 emoji、网址或代码时，系统沿用最近一条客户自然语言；没有可参考的历史消息时使用简短的语言中性回复。

## 边界

“商家补充要求”是附加偏好，不是系统提示词，不能覆盖知识事实、安全规则、客户消息语言或人工确认要求。关闭 emoji 是表达偏好，不会改变回答内容的事实来源。Widget 欢迎语应在渠道设置中维护。
