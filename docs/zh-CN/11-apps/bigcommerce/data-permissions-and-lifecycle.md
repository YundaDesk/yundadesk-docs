# BigCommerce 数据权限与应用生命周期

YundaDesk 将 BigCommerce 店铺授权与 YundaDesk 工作区成员权限分开管理，并将店铺能力限制为客服所需的只读上下文与自己的店面 Widget。

## 读取哪些数据

| 对象 | 用途 | 数据边界 |
|---|---|---|
| 店铺 | 标识会话来源并显示店铺基本信息 | 店铺标识、名称、公开地址、币种等基本信息 |
| 客户 | 在工作台关联客户 | 平台客户标识、邮箱、显示名称，以及无需读取地址即可取得的可选国家信息 |
| 订单 | 帮助客服回答订单问题 | 订单标识、状态、金额、币种、商品摘要和时间 |
| 商品与变体 | 提供购买商品上下文 | 商品与变体标识、名称、SKU、价格和可用状态 |
| 购物车与弃购 | 提供安装后产生的购物车上下文 | 购物车标识、状态、金额、商品摘要和时间；没有历史回填 |

YundaDesk 不保存收货或账单地址、电话号码、付款信息、完整 IP 信息或 BigCommerce 原始响应。购物车上下文不保存地址或优惠券。

## 不会执行的操作

YundaDesk 不会：

- 修改、取消或退款订单；
- 修改库存、商品、客户或折扣；
- 修改结账流程或处理付款；
- 根据历史购物车补造弃购记录；
- 自动向弃购客户发送营销消息。

BigCommerce 会自动为所有应用加入平台的基础店铺访问，因此授权页可能显示 **View and modify basic store information**；YundaDesk 不使用这项默认访问修改店铺设置。YundaDesk 实际执行的唯一店铺写入是管理自己的店面 Script，且管理员仍需在应用内逐店面确认启用、停用或修复。

## 实时事件与同步

Store、Customers、Orders 和 Products 可以从应用状态页手动发起只读同步。客户、订单、商品、库存和购物车变化也会通过 BigCommerce Webhook 更新。

购物车和弃购仅从应用安装且 Webhook 健康之后开始记录。页面显示的授权成功不等于每类资源都已产生数据；请使用不包含真实个人信息的测试客户、商品、订单和购物车逐项验证。

## 多人访问

BigCommerce 店铺可以让多个已获授权用户打开 YundaDesk，但 BigCommerce 身份不会绕过 YundaDesk 权限：

1. 店铺所有者首次安装并把店铺绑定到一个工作区。
2. 其他 BigCommerce 用户第一次打开应用时，必须在新标签页登录为该工作区已有的 YundaDesk 成员。
3. 普通成员只能执行其 YundaDesk 角色允许的操作。
4. 同步、Webhook 修复、店面启停或 Script 修复需要应用管理权限。

从 BigCommerce 移除某个用户的 YundaDesk 应用访问，会结束该用户的 BigCommerce 应用会话，但不会自动删除其独立的 YundaDesk 工作区成员身份。需要时请由工作区管理员另行管理成员。

## 重新授权

如果店铺令牌失效、授权被撤销或所需权限发生变化，应用会显示需要重新授权，并暂停同步和店面状态检查。

1. 由 BigCommerce 店铺所有者打开应用。
2. 按页面提示重新安装或重新授权 YundaDesk。
3. 重新打开应用，确认授权和工作区均为 **Connected**。
4. 检查 Webhook 与店面 Script 状态；只有页面明确提示缺失时才执行经确认的修复。

不要重复使用旧的账号连接链接，也不要把它转发给其他用户。

## 停用店面聊天

如果只想停止某个店面的 Widget：

1. 打开 **Apps → My Apps → YundaDesk**。
2. 在 **Storefront chat** 找到该店面。
3. 选择 **Disable**。
4. 使用隐私浏览窗口确认该店面不再加载 Widget。

其他已启用店面和只读店铺同步不会因此停止。

## 卸载应用

只有确定不再需要整个店铺连接时才卸载：

1. 在 BigCommerce 控制面板打开 **Apps → My Apps**。
2. 找到 YundaDesk，打开应用操作菜单并选择卸载。
3. 阅读 BigCommerce 的确认提示并确认。

卸载后，YundaDesk 会停止该店铺的同步和事件处理，结束应用会话，并立即拒绝该店面的 Widget 配置。BigCommerce 会清理该应用创建的 Webhook 和自动卸载 Script。与该店铺授权产生的数据会按 YundaDesk 隐私政策进入清理流程。

以后重新安装会创建新的授权，并要求再次明确选择 YundaDesk 工作区；旧连接链接和旧授权不能继续使用。

## 常见故障

### Widget 没有显示

- 确认目标店面状态为 **Active**，而不是只完成了应用安装。
- 等待一分钟，再强制刷新公开店面。
- 确认正在测试应用中显示的准确 HTTPS 店面地址。
- 检查 Cookie consent 设置是否允许 functional Script。
- Blueprint 或未验证 headless 店面不受支持。

### Script 显示缺失

YundaDesk 不会在状态检查时自动重建。确认 Script 的确由管理员删除后，使用有应用管理权限的成员选择 **Repair Script** 并确认。

### Webhook 需要修复

使用有应用管理权限的成员选择 **Repair webhooks**，阅读提示后确认。修复完成前，实时变化可能不会及时进入 YundaDesk。

### 同步没有数据

确认测试店确实包含当前可见的合成客户、订单和商品，然后分别为相应资源选择 **Sync now**。购物车和弃购只处理安装后的新事件，不能通过手动同步补回历史记录。

如果问题持续，请按[准备有效的支持请求](../../10-troubleshooting/contact-support.md)整理店铺公开地址、问题发生的大致时间、页面显示的非敏感状态和复现步骤。不要发送密码、API 密钥、客户地址、电话号码或完整订单记录。
