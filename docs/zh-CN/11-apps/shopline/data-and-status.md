# 查看 SHOPLINE 店铺数据、权限与接入状态

SHOPLINE 的**店铺数据**与**前台聊天**分别显示状态。数据已连接说明授权连接可用；是否显示聊天、是否能收发消息，需要分别检测和测试。

## 应用读取哪些数据

| 只读权限 | 用途 |
|---|---|
| 店铺信息 | 确认店铺身份和地址 |
| 客户 | 为客户服务提供可关联的客户资料 |
| 订单 | 查询订单、付款、商品明细与履约信息 |
| 商品 | 提供商品和变体相关的客服上下文 |

这组权限不授予退款、取消订单、修改地址或改库存的操作能力。能读取数据，也不意味着每类数据都有单独的全店管理页面，或所有历史数据已经同步完成。

## 查看接入状态

在 YundaDesk 打开**应用 → SHOPLINE → 查看店铺状态**，先核对店铺地址，再查看两项状态。

| 显示 | 含义与下一步 |
|---|---|
| 店铺数据：已连接 | 数据授权连接可用；仍需检查你要查询的实际订单 |
| 店铺数据：需要重新授权 | 使用有权限的账号按页面提示重新授权 |
| 店铺数据：连接异常 | 尝试测试连接并记录页面提示，按排错文章处理 |
| 前台聊天：待验证 | 尚未完成前台检测；先确认主题已开启聊天，再打开店铺并检测 |
| 前台聊天：检测中 | 本次检测尚在进行，请保留打开的店铺页面 |
| 前台聊天：已嵌入 | 本次检测已确认聊天加载，接着验证消息收发 |
| 前台聊天：上次验证通过 | 曾经验证成功，不代表当前访问已重新检测 |
| 前台聊天：未检测到嵌入 | 本次未检测到聊天加载，检查主题、保存结果及店铺访问情况 |
| 前台聊天：需先恢复连接／配置异常 | 先按当前页面提示处理连接或配置问题，再重新检测 |

## 三个按钮分别检查什么

- **测试连接**：检查店铺数据连接。成功不等于聊天入口已经显示。
- **打开店铺并检测**：打开对应店铺前台并检查聊天是否加载。完成后仍需测试消息。
- **刷新状态**：读取最新状态；不会代替在 SHOPLINE 中开启并保存组件。

## 在客户会话中查看订单

1. 在**收件箱**打开需要服务的客户会话。
2. 查看右侧客户信息中的订单区域，核对订单所属店铺。
3. 有可匹配的客户邮箱和订单时，查看返回的订单状态、金额、商品及履约信息。
4. 没有匹配结果时，先确认客户提供的邮箱与下单邮箱一致，再检查店铺连接和页面错误提示。

匿名访客打开聊天窗口，不会因此自动拥有某位店铺客户的订单。没有订单信息也不等于主题聊天安装失败。不要在公开聊天或截图中暴露其他客户的订单资料。

安装成功也不表示已经配置 AI 自动接待或自动催付；这些任务需按各自页面的能力和配置完成。遇到具体异常，阅读[接入排错与连接管理](./troubleshooting-and-lifecycle.md)。
